# Step 1: User City Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `city` to every user, let users set it via an autocomplete modal on the feed page, and show it on swipe cards.

**Architecture:** One nullable column on the existing `user` table (no new table), threaded through the profile/feed API responses, plus a small modal component that autocompletes via Open-Meteo Geocoding (free, no key) and saves through the existing `PATCH /api/profile/edit`.

**Tech Stack:** Drizzle ORM + Neon (`drizzle-kit push` — repo has no migrations folder), Express 5 + zod, React 19 + Tailwind v4.

**Spec:** `docs/superpowers/specs/2026-11-09-step1-city-design.md`

## Global Constraints

- City values: trimmed string, 1–100 chars, nullable/optional in the edit schema.
- `city` must appear in `GET /api/profile/view`, `GET /api/user/feed`, `GET /api/user/requests/received`, `GET /api/user/connections`.
- No lat/lng, no distance.
- Landing-page styling: `vybe-*` palette, pill ghost buttons, `font-heading` headings.
- Verification: `tsc -b` + `vite build` (frontend), backend typecheck/build; no test framework exists (ruling carried from the feed work).

## Review Focus

- User with no city — card omits the line cleanly; modal does not open in a loop.
- Open-Meteo failure/timeout — modal still allows typing/retry; no crash.
- City save failure — error surfaced, modal stays open with the typed value.
- Existing Google users with null city — no backend error on feed/profile responses.
- Very long city names — card line truncates, doesn't break layout.
